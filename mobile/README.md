# STG Schülerzeitung – Mobile App (v2)

Cross-platform app (iOS + Android) for the school newspaper of the Städtisches Gymnasium Bad Segeberg, https://stg-sz.net. Built with Expo SDK 57 / React Native 0.86 and Expo Router. It talks to the WordPress site through a small must-use plugin (`../wordpress/mu-plugins/stg-app`) that exposes the `stg/v1` REST namespace.

## Run it locally

Prerequisites (already set up on the dev Mac): Node 22, JDK 17, Android SDK with platform 36 + an AVD, Xcode 26.4+ with an iOS 26 simulator runtime, CocoaPods.

```sh
cd mobile
npm install

# Android (emulator "Pixel_9_API_36" or any connected device)
npx expo run:android

# iOS simulator
npx expo run:ios

# afterwards, only the JS bundler is needed
npx expo start
```

Tip: local Android builds compile native code for four CPU architectures by default. For the emulator or a modern phone, one is enough and it halves build time and disk use:

```sh
ORG_GRADLE_PROJECT_reactNativeArchitectures=arm64-v8a npx expo run:android
```

`android/` and `ios/` are generated by `expo prebuild` and git-ignored (continuous native generation). Change native config in `app.json`, not in the generated projects.

```
  (tabs)/                native tabs: start, ressorts, suche (search role), gemerkt, redaktion
  artikel/[id].tsx       article reader
  ressort/[id].tsx       category feed ("alle" = everything)
  autor/[id].tsx         author page
  kommentare/[id].tsx    comments thread: docked composer, saved identity, pending echo, sent card
  seite/[slug].tsx       WordPress pages (Über uns, Datenschutz)
  einstellungen.tsx      settings (appearance, text size, push)
src/api/                 API client, TanStack Query hooks, comments, persisted cache
src/api/html/            Gutenberg HTML -> block model parser (renders natively)
src/components/article/  block renderer, rich text, lightbox, link handling
src/components/cards/    hero / card / row / tile / category / author cards
src/components/ui/       primitives: Txt, Icon (SF Symbols + Material), Tap, Chip, Avatar, Glass, Skeleton …

assets/                  fonts, icons (incl. iOS Icon Composer bundle for Liquid Glass icons), wordmarks
```

## Design notes

- Headlines use **Barlow Condensed**; body and UI text use the platform system font so the app feels native on both platforms.
- Brand colour is the site's crimson `#99183F`; each Ressort has its own accent colour, emoji and icon delivered by the API.
- Tab bar, headers, search bar and sheets are native (Liquid Glass on iOS 26, Material 3 on Android). Custom floating surfaces use `Glass` (glass → blur → tonal fallback).
- The loading indicator is the two dots of the "Ü" from the masthead.
- Articles are rendered natively from the WordPress HTML: paragraphs, headings, images (tap for lightbox), galleries, quotes, lists, YouTube/Vimeo embeds, video, audio, tables, files, buttons, covers and collapsibles. Unknown markup falls back to a WebView.

## Push notifications

Expo's push service is free (no cost, 600 notifications/s per project). The project is linked to EAS as `@gereonelvers/stg-schuelerzeitung` (`extra.eas.projectId` in `app.json`), which is all the app needs to mint tokens. Since SDK 53 **Expo Go cannot receive push notifications**, so testing needs a development build.

**Android (free, Firebase):**
1. Firebase Console → create project → add an Android app with package `net.stgsz.app` → download `google-services.json` into `mobile/` (git-ignored).
2. `app.json` → `"android": { "googleServicesFile": "./google-services.json", ... }`.
3. Firebase Console → Project settings → Service accounts → *Generate new private key* (JSON, git-ignored).
4. `npx eas-cli credentials -p android` → *production* → *Google Service Account* → *Manage your Google Service Account Key for Push Notifications (FCM V1)* → upload that JSON. (Or expo.dev → project → Credentials → Android → FCM V1 service account key.)
5. `npx expo run:android`, enable "Neue Artikel" in the app's settings, then on the server: `wp stg-app devices` and `wp stg-app test "ExponentPushToken[...]"`.

**iOS (needs the paid Apple Developer account):** `npx eas-cli credentials -p ios` creates/uploads the APNs key; the `aps-environment` entitlement is already generated by the expo-notifications plugin. Real devices only – simulators do not receive APNs pushes.

## Deep links

- Custom scheme: `stgsz://artikel/10751`
- Universal links: `https://stg-sz.net/posts/…/10751/`, `/category/<slug>`, `/author/<slug>` resolve in-app. Android App Links and iOS Universal Links additionally need `assetlinks.json` / `apple-app-site-association` on the site once the signing certificate and Team ID exist.
